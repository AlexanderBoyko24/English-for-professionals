# Настройка приложения

Документ описывает два состояния проекта: как он работает сразу и что нужно
сделать, чтобы включить настоящую авторизацию, вход через Google и общую базу.

---

## 1. Что работает прямо сейчас, без настройки

Сайт запускается без сервера и без ключей — в **локальном режиме**.
Регистрация, вход по почте и паролю, прохождение уроков и сохранение прогресса
работают, но данные лежат в `localStorage` того браузера, где вы их создали.

Что в локальном режиме **не** работает:

* вход через Google;
* просмотр прогресса студентов преподавателем с другого устройства;
* перенос прогресса между браузерами и компьютерами.

Наверху страниц в этом режиме висит жёлтая полоса-напоминание.

### Как открыть сайт локально

```bash
node tools/dev-server.js
```

Затем откройте <http://localhost:5173>.

Открывать файлы двойным щелчком (`file://`) не нужно: так не работают
ни вход через Google, ни обращения к базе.

## 2. Подключение Supabase

Supabase даёт базу данных, регистрацию, вход через Google и разграничение
доступа. Бесплатного тарифа хватает с запасом. Сайт при этом остаётся набором
статических файлов — его по-прежнему можно публиковать на GitHub Pages.

### Шаг 1. Создать проект

1. Зайдите на <https://supabase.com> и создайте аккаунт.
2. Нажмите **New project**, задайте имя и пароль базы, выберите ближайший регион.
3. Дождитесь, пока проект развернётся (1–2 минуты).

### Шаг 2. Создать таблицы

1. В проекте откройте **SQL Editor → New query**.
2. Скопируйте туда целиком содержимое файла [`supabase/schema.sql`](supabase/schema.sql).
3. Нажмите **Run**.

Скрипт создаёт четыре таблицы (`profiles`, `groups`, `group_members`,
`topic_progress`), триггер автосоздания профиля при регистрации и правила
доступа. Его можно запускать повторно — существующие данные не пострадают.

### Шаг 3. Прописать ключи

1. Откройте **Project Settings → API**.
2. Скопируйте **Project URL** и ключ **anon public**.
3. Впишите их в [`assets/config.js`](assets/config.js):

```js
window.APP_CONFIG = {
  SUPABASE_URL: 'https://ваш-проект.supabase.co',
  SUPABASE_ANON_KEY: 'eyJhbGciOi...'
};
```

Ключ `anon public` предназначен для публикации в коде страницы — это не секрет.
Доступ к данным ограничивают правила из `schema.sql`, а не скрытность ключа.
Ключ `service_role` в файлы сайта класть нельзя ни при каких условиях.

После этого жёлтая полоса про локальный режим исчезнет.

### Шаг 4. Настроить подтверждение почты

По умолчанию Supabase требует подтвердить адрес письмом.

* Оставить как есть — надёжнее: **Authentication → Providers → Email**,
  переключатель **Confirm email** включён. После регистрации приложение
  покажет сообщение о письме.
* Для быстрой проверки подтверждение можно временно выключить там же.

## 3. Вход через Google

### Шаг 1. Ключи в Google Cloud

1. Откройте <https://console.cloud.google.com>, создайте проект.
2. **APIs & Services → OAuth consent screen**: тип **External**, заполните
   название приложения и контактную почту.
3. **APIs & Services → Credentials → Create credentials → OAuth client ID**,
   тип **Web application**.
4. В поле **Authorized redirect URIs** добавьте адрес из Supabase
   (**Authentication → Providers → Google**, строка *Callback URL*). Он выглядит так:

   ```
   https://ваш-проект.supabase.co/auth/v1/callback
   ```

5. Сохраните и скопируйте **Client ID** и **Client secret**.

### Шаг 2. Включить провайдер в Supabase

1. **Authentication → Providers → Google**, включите переключатель.
2. Вставьте Client ID и Client secret, сохраните.

### Шаг 3. Указать адреса сайта

**Authentication → URL Configuration**:

* **Site URL** — основной адрес сайта, например
  `https://alexanderboyko24.github.io/English-for-professionals/`.
* **Redirect URLs** — добавьте туда же адрес страницы входа и адрес для
  локальной разработки:

  ```
  https://alexanderboyko24.github.io/English-for-professionals/auth.html
  http://localhost:5173/auth.html
  ```

Без этих адресов Google вернёт пользователя на страницу с ошибкой.

### Про роль при входе через Google

Google не передаёт роль. Поэтому:

* если пользователь нажал кнопку Google на вкладке **Регистрация**, приложение
  запоминает выбранную роль и проставляет её сразу после возврата;
* если он вошёл через Google без выбора роли, по умолчанию будет **студент**.

Роль всегда можно поправить вручную: **Table Editor → profiles**, колонка `role`,
значения `student` или `teacher`.

## 4. Публикация на GitHub Pages

1. В репозитории откройте **Settings → Pages**.
2. **Source** — ветка `main`, папка `/ (root)`.
3. Сохраните. Через минуту сайт будет доступен по адресу вида
   `https://<логин>.github.io/English-for-professionals/`.

После публикации не забудьте добавить этот адрес в **Site URL** и
**Redirect URLs** в Supabase (см. шаг 3 выше).

Файл `assets/config.js` попадёт в публичный репозиторий вместе с ключом
`anon public` — так и задумано.

## 5. Как заводить преподавателей

Роль выбирается при регистрации. Если аккаунт уже создан со студенческой ролью,
поменяйте её в Supabase: **Table Editor → profiles → role** → `teacher`.

Преподаватель видит:

* поиск по всем студентам (по ФИО и почте);
* свои группы и их состав;
* прогресс студентов **своих** групп.

Прогресс чужих студентов недоступен — это ограничение на уровне базы, а не
интерфейса, обойти его через консоль браузера нельзя.

## 6. Как устроен прогресс

Прогресс хранится по одной строке на пару «студент + тема» в таблице
`topic_progress`. Поле `state` содержит ответы студента, поэтому при повторном
заходе в тему заполненные поля, расставленные слова и отмеченные упражнения
восстанавливаются.

Процент по упражнению считается так:

| Упражнение | Как считается |
|---|---|
| Vocabulary, Read & Translate, Video | кнопка **Mark as learned** → 100% |
| Translate Word Combinations, Translate into English | доля верно переведённых словосочетаний |
| True / False | доля верных ответов |
| Match Terms, Match the Picture, Mind Map, Logical Sequence, Label the Diagram | кнопка **Check** считает долю верных пар |
| Fill in the Table | кнопка **Check** у каждой строки |
| Fill in the Gaps, Word Order | кнопка **Check** у каждого предложения |
| Listening: Gap Fill | каждый верно выбранный вариант |
| Reading Practice | доля распознанных слов после **Stop mic** |
| Финальный тест | процент правильных ответов, засчитывается лучший результат |

Процент по теме — среднее по всем её упражнениям.
Процент по направлению — среднее по темам, по курсу — среднее по направлениям.

Распознавание речи в Reading Practice работает в Chrome и Edge; в других
браузерах упражнение покажет предупреждение.

## 7. Как добавить материал

### Новая тема в существующее направление

1. Положите данные урока в `data/<курс>/<направление>/<номер>.js`
   по образцу соседних файлов (объект `window.LESSON`).
2. Создайте страницу `<курс>/<направление>/<номер>.html` — скопируйте любую
   соседнюю и поменяйте в ней номер темы в двух местах:
   `window.TOPIC` и путь к файлу данных.
3. Допишите тему в список `topics` в [`assets/catalog.js`](assets/catalog.js).

Картинки кладутся в `<курс>/<направление>/images/<номер>/`,
аудио — в `audio/<номер>.mp3`, видео — в `video/<номер>.mp4`.

### Новое направление или курс

Опишите его в `assets/catalog.js`. Пока в направлении `ready: false`,
оно показывается в списке с пометкой «в разработке» и не кликается.

## 8. Если что-то пошло не так

**Жёлтая полоса про локальный режим не исчезает.**
Проверьте `assets/config.js` — оба поля должны быть заполнены. Откройте консоль
браузера: при неудачном подключении там будет строка
«Не удалось подключиться к Supabase».

**После входа через Google возвращает на страницу с ошибкой.**
Адрес страницы не добавлен в **Redirect URLs** в Supabase либо Callback URL не
прописан в Google Cloud.

**Преподаватель не находит студентов.**
Убедитесь, что у аккаунта в таблице `profiles` роль `teacher`, а у студентов
заполнено поле `full_name` — поиск идёт по ФИО и почте.

**Прогресс не сохраняется.**
Внизу слева при каждом действии всплывает подпись «Прогресс сохранён».
Если вместо неё «Не удалось сохранить» — смотрите ошибку в консоли браузера;
чаще всего в базе не выполнен `schema.sql`.
